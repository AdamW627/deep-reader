# Windows 适配评估

本次适配可供其他 Windows 用户复用，没有绑定特定用户名、盘符或开发机目录。范围是 Python 3.12 / Node.js 20+ 的原生源码安装；npm 自动安装器仍使用 macOS 专用运行时和平台检查。

## 可复用的改动

| 改动 | 原因与适用范围 |
| --- | --- |
| 显式 UTF-8 读写 | 避免 Windows 默认代码页影响中文论文、研究背景、导读和 JSON；macOS / Linux 同样采用确定的编码。 |
| 共用原子写入 | JSON 和生成资料共用逻辑；只对 Windows 文件占用相关错误有限重试，其他错误立即抛出。写入失败清理临时文件，保留旧内容。 |
| 路径分隔符兼容 | 工具进度兼容两种路径分隔符，测试中以 POSIX 格式比较相对路径。 |
| Windows 启动器 | 从脚本位置定位项目，无需激活虚拟环境；支持 PowerShell 5.1、CMD、自定义端口、后台进程与标准输出/错误日志。 |
| 平台测试差异 | POSIX 权限断言在 POSIX 上保留；Windows 不把 chmod 等同于 ACL。符号链接仅在 WinError 1314 时跳过。 |
| 发布与 CI | 源码包白名单包含两个 Windows 入口；检查矩阵覆盖 Windows、Linux、macOS。 |

## 整理时修正的问题

- 两处重复的文件替换重试合并到 `backend/storage.py`，增加失败清理和有界重试的回归测试。
- 符号链接测试不再跳过所有 `OSError`，避免隐藏真实路径错误。
- 查看日志不再清空已有日志，并同时展示 uvicorn 常用的标准错误输出。
- 停止服务校验进程路径及启动时间，避免陈旧 PID 指向其他程序；旧版 PID-only 记录需要手动处理。
- PowerShell 脚本采用 ASCII 提示文字，避免无 BOM 的中文脚本在 Windows PowerShell 5.1 中被错误解码。
- 发布脚本生成的相对路径统一为 `/`，避免 Windows 反斜杠造成重复归档路径。

## 验证与边界

后端回归测试覆盖中文与 Unicode 内容、Windows 短暂和持续文件占用、非 Windows 错误不重试、序列化失败后保留旧文件，以及两种路径分隔符。真实启动器使用独立端口验证；前端与扩展沿用现有自动检查。

本机 Windows / Python 3.12 验证结果：后端 60 项通过、2 项因符号链接权限跳过；前端单元测试 12 项、浏览器交互 32 项、扩展 7 项通过；npm 启动器 1 项通过、1 项 macOS 专用测试跳过；前端生产构建通过。Linux / macOS 由新增 CI 矩阵继续验证。

真实模型请求和 SDK 外部工具的所有行为仍需配置供应商 Key 后验证，自动测试使用模拟模型。Windows 文件访问控制取决于目录继承的 ACL，不能从 POSIX 文件模式推断私密性。扫描 PDF、npm Windows 自动安装和多用户服务不在本次适配范围内。
